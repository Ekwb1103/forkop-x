# Адресные исправления по issues Tachyon

Дата: 2026-10-18. База Forkop main e387b684; Rust X main 7d76188.
Изменения локальные, без публикации релиза или установки на операторский роутер.
Telegram CIDR fallback исключён по запросу пользователя. HTTP auth_user не менялся:
Forkop маршрутизирует секционные mixed-inbound по отдельным тегам.

## Изменения

- [#101](https://github.com/Dushnilin/tachyon/issues/101): импорт pcs из TLS
  ссылок VLESS/Trojan и pinnedPeerCertSha256 из Xray JSON. SHA-256 hex,
  hex с двоеточиями и base64 нормализуются в certificate_sha256; несколько
  пинов сохраняются, дубликаты удаляются. Ошибочный пин прерывает импорт.
  Экспорт, отдельный путь ручной генерации и восстановление старого URI-кэша
  сохраняют пин. UCI insecure
  не меняется; обычная проверка цепочки сертификатов не ослабляется.
- [#118](https://github.com/Dushnilin/tachyon/issues/118): существующее
  подавление DNS HTTPS теперь выдаёт predefined/NOERROR с пустым ответом.
  Политика SVCB и use-application-dns.net не изменялась.
- [#157](https://github.com/Dushnilin/tachyon/issues/157): Rust X сохраняет
  fakeip_domain независимо от sniffed SNI и destination. Inline domain,
  suffix, regex, интерпретируемые, индексированные и mmap rule-set matchers
  проверяют кандидатов согласованно. На обычном lowercase пути новые
  коллекции в heap не создаются.
- [#160](https://github.com/Dushnilin/tachyon/issues/160): ручной group delay
  обходит все листья Selector/URLTest, дедуплицирует их и ограничивает
  параллелизм восемью задачами. Учитываются общий timeout, частичный успех,
  очистка устаревшей истории и URLTest tolerance. Выбор Selector сохраняется.
  Результаты группы, пережившей reload, не применяются к новой генерации
  при обнаруженном несовпадении RouterInner.
- [#154](https://github.com/Dushnilin/tachyon/issues/154): H2 XHTTP учитывает
  XMUX max_concurrency. Сначала используется доступная ёмкость существующих
  соединений, затем открывается новое. maxConcurrency не превращается в
  глобальный предел соединений; явный maxConnections сохраняет отдельное
  поведение. Drop/отмена освобождают счётчик и будят ожидающих.

## Ограничения совместимости

Sing-Box X 1.0.4 и Extended 2.7.2 отвергают certificate_sha256 как неизвестное
поле. Проверено настоящими executable. Генератор исключает такие узлы и
зависимые detour/пустые группы из рабочего конфига неподдерживающего ядра,
с предупреждением; исходный пин остаётся в кэше. Если подходящих узлов нет,
генерация завершается ошибкой, сохраняя предыдущий конфиг. Явная ручная
настройка с пином на таком ядре также возвращает ошибку. Пин никогда не
снимается для разрешения соединения. Rust X принимает поле и проверяет его
в обоих TLS стеках. Распознаются форматы версии -rust-x. и текущий -tachyon.
Неизвестные Go-версии считаются неподдерживающими до отдельной проверки.

Общая секционная политика IPv4/IPv6 из #153 не внедрена: частный upstream
substring-патч для --filter-l3 не представляет согласованную DNS/route/nft
политику. Fallback #148 не перенесён: он удаляет CIDR и диапазоны портов
при отсутствии interval concat поддержки. Нужна отдельная реализация,
сохраняющая семантику правил. На наших x86 VM такого отказа ядра не было.

## Проверки

Существующие VMware OpenWrt 25.12.5 (192.168.1.1) и 24.10.8
(192.168.241.2), x86_64. Пакеты, enabled/running состояние и контрольные
суммы установленных executable/UCI/runtime config/nft сохранены перед
тестами в artifacts/issue-review. Первый этап использовал только
/tmp/forkop-issues-20261018 и отдельные loopback-порты. Дополнительный
пакетный этап, описанный ниже, останавливал и восстанавливал службы ВМ.

На обеих VM прошли:

- ucode импорт/экспорт пинов, Xray JSON, восстановление кэша, несколько
  пинов, отсутствие пина и отказ при неверном формате;
- генерация DNS для 1.12/1.13/1.14; на VM24 тот же скрипт запускался ash
  с подставленным ROOT_DIR, поскольку bash не установлен;
- subscription_cache_relocation, включая полный offline prepare-caches,
  и json_outbound_connection;
- статические Rust X executables: FakeIP/ECH (1), imported_pins (1),
  group_delay (3), rule_set_compiled (13), urltest_timing (2), XHTTP unit/wire
  tests (25). Итого 45 адресных Rust-тестов на каждой VM.

FakeIP тест моделирует ECH outer SNI в ConnContext, затем выполняет настоящие
FakeIP reverse и resolve; это не обмен с внешним ECH сервером. TLS тест
передаёт ping/pong с верным пином и отклоняет неверный, отдельно для core
и rustls. На VM25 входной пин получен ucode-парсером из URI; на первом
VM24 запуске использована встроенная эквивалентная фикстура.

Новые ucode-тесты пинов и DNS также запущены на сохранённом исходном коде
и закономерно упали; после исправлений прошли. Host WSL/Linux прошёл
адресные Rust-тесты. cargo fmt и git diff --check проверяются отдельно.
После установки компонента Clippy прошёл для core-runtime --lib --tests,
no-default-features/features rust-x, x86_64 musl, с -D warnings и явным
-A dead_code для существующих отключённых/смежных протокольных модулей.
Это адресная проверка профиля Rust X, а не полный CI всех legacy features.

Стенд Xray 26.9.8 использует тестовую CA и сертификат из repository fixtures,
TLS с проверкой CA, ALPN h2, VLESS XHTTP mode=auto, imported extra
maxConcurrency=1. На каждой VM прошли две волны по шесть одновременных
скачиваний по 256 KiB (с побайтовым cmp) и загрузка 64 KiB с проверкой длины.
Это проверка конкретного TLS/H2 packet-up сценария с auto, а не всех XHTTP
профилей, REALITY или реальных подписок провайдеров.

DNS wire: на обеих VM финальный Rust X возвращает NOERROR/ANSWER:0 на HTTPS,
и правильный A адрес из тестового hosts-сервера. На VM25 тот же DNS-конфиг
проверен также Extended 2.7.2. Дополнительный тест совместимости проверил
фильтрацию пинов для Go X/Extended и сохранение для Rust X, включая
реальные check обоих ядер, неизменность кэша и предыдущего конфига при отказе.

SHA-256 отдельного тестового ядра совпал локально и на обеих VM:
`c457f2222fab40608d16dad4171e3ad858f96efd95130967649f7435d4d69a39`.
Это локальная сборка, не подписанный опубликованный пакет.

После тестов совпали списки пакетов, enabled/running состояние, PID рабочих
ядер и четыре контрольные суммы executable/Forkop UCI/DHCP UCI/runtime JSON.
Штатный DNS ответил на обеих VM. Полный текстовый hash nft изменился;
он включает динамические данные работающего стенда, поэтому утверждения
о побайтовой неизменности nft нет. Тесты не выполняли nft/UCI/service apply.
Отдельных процессов rust-x/xray после cleanup не осталось. Временные каталоги
удалены после выгрузки evidence; исходно выключенная VM24 штатно выключена.
VM25 оставлена работающей. Cargo fmt --check и оба git diff --check прошли.

Локальные harnesses, финальные результаты и архивы wire-логов сохранены
в artifacts/issue-review; ключи операторских SSH туда не копировались.

По просьбе пользователя продолжены тесты Forkop X и Rust X; публикация,
canary, теги и установка на операторский роутер не выполнялись.

  15 тестов. Cargo fmt и оба git diff --check прошли.

Пакетные тесты сохраняли исходные пакеты, службы, /etc/config,
/etc/forkop и /etc/forkop-backups в /tmp/forkop-package-review-20261018.
