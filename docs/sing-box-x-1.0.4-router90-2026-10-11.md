# Sing-Box X 1.0.4 installation, 2026-10-11

At the owner's request, replaced Rust X 0.0.7-r1 with Sing-Box X 1.0.4-r1
on 192.168.90.1 (GL-MT6000, OpenWrt 25.12.5, aarch64_cortex-a53).
No rollback package or old executable was staged.

Prepared release 1.0.4 on the existing main branch, commit
`c5f0134d4b9ea3b38651564d7dd978428a47aed2`.
[Build and release CI](https://github.com/Screamshow/forkop-x-engine/actions/runs/38153415800)
completed successfully, including normal and race test suites, both architecture
builds and package checks. Published the
[release](https://github.com/Screamshow/forkop-x-engine/releases/tag/1.0.4),
then used the existing mirror publisher to sign APK on the mirror and update
the stable catalog and signed package feed. Public catalog, immutable manifest,
all seven asset lengths/SHA-256 and both architecture feed signatures passed.

The router downloaded only from the mirror. Before stopping Forkop, verified
APK signature, package name/version/architecture, catalog URL/length/hash,
extracted binary provenance and current runtime configuration compatibility.
The package-manager replacement removed only rust-x and added only sing-box-x;
existing dependencies remained installed.

Installed executable reports `1.14.2-x-1.0.4`; backend variant is `x`.
Binary SHA-256:
`bd5c4682d84b4c6a85f7303ae0f7ebba8761cf4463e736450778a4023134e4f3`.
Exactly one managed core process was running. Forkop reported running/enabled
with DNS configured. Forkop and sing-box UCI files were byte-identical before
and after. DHCP user settings were unchanged; its internal
`forkop_dns_transaction_id` was regenerated by the normal stop/start cycle.

Post-install checks passed: Clash API, manual tests of three real VLESS nodes
(52/60/65 ms), provider group URLTest, and HTTPS through the normal SOCKS
inbound (HTTP 204). Baseline Rust X samples were 111/143/113 ms. These were
different live network samples and are not a controlled performance benchmark.
Priority failover/recovery had already passed on both OpenWrt test VMs; no
forced failure of live customer routes was performed during installation.

Private router snapshots and API headers stayed on the router and were removed
after verification. Local evidence under
`artifacts/sing-box-x-public-verification/1.0.4/` contains public release data
and anonymous check summaries, with no subscription credentials or HWID.
