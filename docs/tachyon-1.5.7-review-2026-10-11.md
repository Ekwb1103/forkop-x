# Tachyon 1.5.7: применимость к Forkop X

Проверены публичные release notes и diff `1.5.6...1.5.7` через GitHub API,
сопоставлены с текущими локальными исходниками Forkop и Rust X.
Это статическая проверка: VM, пакеты и службы не менялись, runtime-тесты
не выполнялись. Изменения реализации и публикация релиза не выполнялись.

Источники:
- https://github.com/Dushnilin/tachyon/releases/tag/1.5.7
- https://github.com/Dushnilin/tachyon/compare/1.5.6...1.5.7

## 1. Кэш при смене ядра — адаптировать, высокий приоритет

Forkop `singbox/generator.uc` использует общий settings.cache_path,
по умолчанию `/tmp/sing-box/cache.db`, с `store_fakeip: true`.
В components/action.uc защиты кэша при смене варианта не найдено.
Rust X использует собственную реализацию чтения/атомарной перезаписи bbolt
в crates/core-runtime/src/cache_file.rs. Она стремится к совместимости
с reference, поэтому сам факт разных языков не доказывает несовместимость.
Однако общий файл пересекает границы реализаций, а полная матрица
совместимости X/Extended/Extended compressed/Rust X не подтверждена.

Upstream называет это изоляцией, но diff реализует удаление общего файла,
включая glob cache.db* в нескольких стандартных каталогах. Так копировать
не следует: это затрагивает лишние файлы, не сохраняет кэш для rollback
и не проверяет успех удаления. Признак compressed сам по себе также
не доказывает иной формат БД: упаковка исполняемого файла не меняет схему.

Рекомендация: отдельный управляемый путь по семейству/формату кэша,
миграция существующего пути без потери пользовательских файлов,
либо транзакционное сохранение только фактически используемой БД после
остановки владельца. При rollback восстанавливать согласованную пару
ядро/кэш. Не очищать при обычном обновлении того же совместимого семейства.
Проверки: переходы в обе стороны, custom cache_path, ошибка запуска,
ошибка файловых операций, сохранение FakeIP внутри семейства и восстановление.
Смена БД может обесценить FakeIP-адреса, уже закэшированные LAN-клиентами;
это нужно проверить при переходах.

## 2. OpenWrt/APK и kmod — основное уже есть

forkop/Makefile и build.sh уже включают kmod-nft-tproxy, kmod-tun,
kmod-inet-diag для IPK/APK. Пакетные операции поддерживают apk/opkg;
есть предыдущие интеграционные проверки существующей OpenWrt 25 VM.
Поэтому рекламируемая «нативная поддержка» не является отсутствующей
функцией Forkop. Совместимость всех будущих 25.12+ из этого не следует.

В init.d/forkop нет аналогичных принудительных modprobe. Полезно отдельно
проверить cold boot минимальной VM и наличие nft_tproxy/tun/inet_diag,
включая встроенные модули. При подтвержденной необходимости добавить
проверку готовности ресурсов и точную диагностику. Не копировать mknod
или установку пакетов при каждом старте без подтвержденной причины.

## 3. DNS failover — конкретные upstream дефекты у нас отсутствуют

Forkop dns_failover.uc не оборачивает dns_failover_apply в timeout 10,
не имеет upstream повтора через 1 секунду при мертвом main DNS,
уже содержит 90-секундный grace по provenance управляемого процесса.
Forkop lifecycle.uc использует остановку/замену управляемого runtime,
а не upstream SIGHUP. Увеличение timeout до 45 и ожидания SIGHUP до 15
секунд не являются прямыми исправлениями Forkop.

Остается отдельный предмет проверки: wait_dns_failover_state(..., 8)
и корректный rollback на медленном старте. Расширять ожидание следует
по результатам сценария, с проверкой PID/готовности и сохранением резервной
копии, если восстановление не удалось. В текущем пути backup удаляется
после попытки восстановления без подтверждения его полного успеха.

Watchdog Forkop — instance procd службы Forkop, имеет защиту перехода
пакетного обновления. Upstream watchdog существенно иной. Его сверка
версий обрезает prerelease/package revision до x.y.z и потому не подходит
нашим canary. Автоперезапуск по такой сверке переносить не нужно.

## 4. Валидатор — исправление неприменимо

В Forkop validator.uc нет вызова неопределенной sing_box_is_tachyon_core,
который исправлен upstream, и нет той матрицы отдельных действий
mieru/warp/masque/snell/openvpn. Forkop уже проверяет generated config
командой sing-box check. Наличие протокола в Rust X не означает наличие
соответствующего действия/генератора в Forkop. Новый helper переносить
не требуется; при будущих действиях нужны собственные capability-проверки.

## 5. Загрузчик — небольшая полезная адаптация

components/action.uc Forkop уже пробует proxy первым для metadata и файлов,
затем direct. В ruleset_cache.uc есть connect timeout 8 / max time 30;
в subscription/cache.uc и components/updates.uc уже используется
low-speed abort 1 байт/с за 15 секунд. Общий загрузчик компонентов
http_get_once пока не имеет low-speed abort.

Имеет смысл добавить консервативный контроль зависания в этот путь и
ruleset_cache.uc. Порог upstream 32 KiB/s за 6 секунд и общий лимит
30 секунд для крупных бинарников слишком агрессивны для слабых каналов.
Сохранить раздельные таймауты metadata/пакетов и проверки длины/SHA-256.
Release notes упоминают socks5h, но diff downloader использует http://;
настройки брать из фактического контракта service proxy Forkop.

## 6. TACHYON_RULESET_SOFT_START — не включать автоматически

В Rust X этот флаг существует в route/rule_set_remote.rs: remote ruleset
может стартовать пустым и загружаться в фоне. Это меняет маршрутизацию
на период загрузки. Проверка кэша не должна незаметно добавлять такое
поведение. Forkop уже имеет собственную подготовку/валидацию ruleset.

## Вывод

Новый релиз Sing-Box X или Rust X по этим изменениям не требуется:
1.5.7 — релиз приложения Tachyon. Первая отдельная задача для Forkop:
защита/изоляция кэша с rollback. Следом — консервативный low-speed abort
в недостающих загрузчиках. Cold boot минимального OpenWrt и медленный
DNS failover — сфокусированные проверки перед дополнительными изменениями.

## Реализация по запросу пользователя

В локальном main добавлен singbox/cache_identity.uc. Генератор выбирает
отдельный физический файл для X, Rust X, Extended и LX по версии ядра.
Extended и compressed используют одну идентичность. Upstream/Tiny
сохраняют исходный cache_path; другие семейства получают суффикс
`.forkop-<family>`. Базовый путь в UCI не меняется. Старые файлы
не удаляются и не импортируются. При возврате к семейству генератор
снова выбирает его прежний файл; обновления внутри семейства сохраняют путь.

При первом запуске X/Rust X после обновления создается новый кэш;
FakeIP в DNS-кэше LAN-клиентов может требовать обновления. Для custom
пути на flash нужно учитывать отдельный файл каждого семейства;
по умолчанию кэши остаются в /tmp. Автоматическая очистка не добавлена,
чтобы сохранить данные для возврата к прежнему ядру.

В components/action.uc и singbox/ruleset_cache.uc добавлен curl
low-speed abort: менее 1 байта/с в течение 15 секунд. Порядок proxy/direct,
таймауты, проверки длины/хэшей пакетов и ruleset сохранены.

На существующей VM OpenWrt 25 (25.12.5), в изолированном /tmp-каталоге,
прошли sing_box_cache_identity.uc (реальный генератор, custom путь,
разделение семейств, сохранение файлов), ruleset_cache.sh (включая новые
curl аргументы) и sing_box_dns114.sh. Пакетное состояние и procd service
list сняты до проверки. Установленный Forkop и службы не изменялись.
Живой переход пакетов и реальное медленное HTTP-соединение не проверялись.
Флаги soft start, kmod и DNS lifecycle не менялись.

### Последующая доработка: очистка после успешного перехода

По дополнительному запросу пользователя сохранение прежней БД теперь
ограничено длительностью транзакции смены ядра. components/action.uc
снимает точный cache_file.path из старого runtime config перед остановкой.
Удаление вызывается только из action_success после подтвержденной готовности
Forkop двумя проверками с интервалом 8 секунд. Ошибка/rollback не вызывает
очистку. При одинаковом пути (обновление внутри семейства, Extended ↔
compressed) файл остается. Удаляется только обычный файл прежней БД;
symlink, каталог и соседние файлы не удаляются. Ошибка удаления выводится
в журнал. Если Forkop был выключен и новое ядро не запускалось, очистки
нет: готовность не подтверждена. Уже оставленные исторические кэши эта
операция не сканирует. Возврат после успешно завершенного перехода создаст
кэш прежнего семейства заново.

На VM OpenWrt 25.12.5 прошли генерация и тесты удаления реальных временных
файлов: успех, отказ перехода, тот же путь, соседний файл, symlink,
каталог и отсутствующая БД. components/action.uc скомпилирован ucode.
Установленные пакеты и procd-службы не менялись; пакетный переход не запускался.
