# Ревью расчёта места при установке sing-box, 2026-10-09

## Подтверждённый результат

Исправление `1b72892c` присутствует в main и в фактически скачанных с публичного зеркала backend-пакетах Forkop 2.1.0 и 2.1.1, в обоих форматах APK/IPK. SHA-256 архивов проверены по публичному releases.json, из каждого архива извлечён action.uc. Все четыре файла совпадают с main:

`9b58164ed18ed7d82242a51bd6d069c35cf6e7ce6181d5944617f9bd6d532800`.

Такая же библиотека установлена на существующих VMware OpenWrt 25 и 24. Проверки не устанавливали и не удаляли пакеты, не меняли конфигурацию и состояние служб. Регрессии создавали временные файлы в /tmp и удаляли их.

Скачан и проверен также публичный IPK Forkop 2.0.0: он содержит прежний расчёт максимума установки/отката с ограниченным вычетом освобождаемого места. Версия backend на пяти устройствах со скриншота неизвестна; доступ к ним не выполнялся.

## Что сейчас считается

В components/action.uc:483 размер APK берётся из размеров файлов манифеста, IPK — из содержимого data.tar.gz. UPX-распаковка в RAM не увеличивает расчёт флеш.

До изменения пакетов проверяются:

* дополнительный объём отката `max(previous_payload - existing_writable_files, 0)` и зависимости, плюс 2048 КиБ;
* свободный /tmp после скачивания архивов: дополнительные резервные копии compressed-варианта плюс 8192 КиБ рабочего места.

После удаления конфликтующего варианта выполняется sync и новый df. Проверяется целевой payload с резервом зависимостей установки/отката и 2048 КиБ. Нехватка места запускает заранее подготовленный откат. Установка X удаляет прежний X, Tiny, Extended или ordinary sing-box перед этой проверкой.

Файлы из ROM, symlink/hardlink и чужая libcronet.so не дают исходного writable-объёма. Подсчёт существующих файлов не обещает столько же освобождённых блоков UBIFS/JFFS2; окончательная проверка использует df.

## Разбор скриншотов

Текущая fixture успешно проходит предварительную проверку при всех свободных объёмах со скриншота: 7928, 7776, 3588, 7572 и 5176 КиБ, если прежний payload уже размещён в writable-слое, без дополнительных зависимостей и при достаточном /tmp.

Но текущий код также воспроизводит **точно те же ошибки** при нулевом writable-объёме:

* previous_payload = 31 139 840 байт: требуется 32 458 КиБ;
* previous_payload = 40 513 536 байт: требуется 41 612 КиБ.

Это подобранные входы для воспроизведения формулы, а не измеренные размеры пакетов клиентских роутеров. Совпадение сообщения само по себе не определяет версию backend и размещение ядра.

Если прежнее ядро находится в ROM, его удаление не освобождает overlay. Реализованный сейчас откат переустанавливает точный прежний пакет в writable-слой, поэтому резерв полного прежнего payload предусмотрен намеренно. Альтернативный откат с возвратом к firmware-файлам потребует отдельной реализации и проверки package-manager state, зависимостей, UCI и runtime.

Актуальный публичный каталог X на момент ревью: 1.0.3, upstream 1.14.2. ARM64 IPK payload 8 634 540 байт, размер архива 8 433 696 байт. Для целевого payload с резервом требуется 10 481 КиБ **после удаления**, без дополнительных зависимостей. При 7928 КиБ до удаления нужно фактически освободить ещё не менее 2553 КиБ; при 3588 — 6893 КиБ. Утверждение «X весит 8,6 МБ, значит места точно хватит» без фактического освобождения и проверки отката не подтверждено.

Для установления причины на каждом проблемном устройстве нужны версия Forkop и hash установленного action.uc, список файлов прежнего пакета, lstat бинарника и writable-копии, df до удаления и лог preflight. Версии 1.13.21 → 1.13.21 в уведомлении об отказе не доказывают, что X был установлен.

## Замечания ревью

### P2: общий installer повторно резервирует скачанный архив X в /tmp

install.sh:2910–2912 измеряет df после download_with_retry, затем требует ещё размер этого уже скачанного архива плюс 8192 КиБ. Архив уже уменьшил показанное свободное место. Это лишний повторный резерв: на ARM64 около 8 МиБ, на x86_64 около 9,3 МиБ. Возможен ложный отказ по временной памяти. Эта ветка не формирует flash-ошибку со скриншотов; компонентный action.uc архив второй раз не считает. При исправлении следует считать отдельно реально предстоящие скачивания/распаковку и сохранять резерв рабочего места.

### P3: описание расчёта в старой документации противоречит реализации

docs/sing-box-package-updates.md:15–24 всё ещё описывает 25% + 8 МиБ для flash и 75% writable-credit. Компонентный backend уже использует прирост отката, 2 МиБ и фактический df после удаления. Эти старые правила сохранились лишь частично в отдельном low-space Tiny пути общего installer и не описывают текущую установку X.

Обновления Tiny/ordinary/Extended в тот же вариант остаются консервативными: собственный пакет перед окончательной проверкой не удаляется, поэтому требуется весь новый payload поверх текущего свободного места. У X собственный пакет удаляется. Это ограничение покрытия исправления; минимальное место для inplace-обновления остальных вариантов отдельно не измерялось.

Скачанные публичные пакеты и извлечённые библиотеки: tmp/storage-review-20261009/. Исходный код не изменён.

## Дополнительная интеграционная проверка по запросу пользователя

После вопроса о возможности проверки на ВМ выполнены реальные операции на **обеих существующих ВМ**: OpenWrt 25 / APK и OpenWrt 24 / IPK. Клиентский роутер для этих проверок не нужен.

До воздействия сохранены список пакетов, состояние служб, UCI и SHA-256 исходного бинарника/backend. Воздействие ограничено ВМ: переустановка исходного X 1.0.2, затем отказ после удаления и отказ установки с подготовленным откатом. ВМ не обновлялись до X 1.0.3 и не перезагружались.

Пакеты X 1.0.2 заново скачаны оператором исключительно с mirror.51343.ru; проверены catalog identity, x86_64, формат, имя/ревизия, длина и SHA-256. Бинарник из каждого архива побайтово сравнен с исходным установленным бинарником соответствующей ВМ. Прямой HTTPS-доступ из OpenWrt 25 к зеркалу завершался connection reset, поэтому тестовый curl обслуживал только точные mirror URL из этой проверенной локальной копии. latest.json закреплён на исходном публичном manifest 1.0.2. Внутри действия сохранились штатные проверки identity/длины/hash.

| Проверка | OpenWrt 25 / APK | OpenWrt 24 / IPK |
| --- | --- | --- |
| Модель нулевого writable-объёма отката, 7928 КиБ: отказ до остановки, PID сохранён | PASS | PASS |
| Штатный backend, writable-ядро, 7928 КиБ до удаления и 17000 после: реальное удаление/установка | PASS | PASS |
| Реальное удаление, df после удаления = 1000 КиБ: точный package/runtime rollback | PASS | PASS |
| Реальное удаление, один искусственный отказ установки: точный package/runtime rollback | PASS | PASS |
| Исходные package/dependency revisions, SHA-256 бинарника/backend, обе UCI, валидная конфигурация, один процесс и DNS | PASS | PASS |

В обоих случаях modeled ROM preflight потребовал 11757 КиБ при 7928 свободных: здесь прежний пакет — X около 9,5 МиБ, а не клиентский Tiny около 30–40 МиБ. После удаления при 1000 КиБ action вернул ошибку с подтверждённым восстановлением предыдущего варианта.

Переустановка и откаты выполнялись **нетронутым production action.uc и настоящим пакетным менеджером**. Подменены транспорт загрузки и показания df. ROM-проверка использовала отдельную копию action.uc с нулевым writable baseline; реальная прошивка с ROM, UBIFS/JFFS2 и реально заполненная флеш не создавались. На VMware rootfs ext4. Это проверка транзакционной логики, не измерение эффективности сжатия или GC флеш.

Добавлен воспроизводимый runner tests/sing_box_storage_low_space_vm.sh. Для запуска нужны заранее проверенные и сохранённые оригинальные mirror manifest/package X 1.0.2 в FORKOP_STORAGE_TEST_WORK и исходно работающая соответствующая ВМ с X 1.0.2. Runner требует FORKOP_TEST_VM=1, сохраняет состояние, создаёт из установленного backend отдельную ROM-модель и выполняет четыре случая. Production backend не заменяется.

Обе ВМ оставлены с исходными X 1.0.2, пакетами и UCI; Forkop работает, по одному процессу sing-box, DNS проверен. Снимки и логи сохранены в root-only /tmp/storage-review-vm-20261009 на каждой ВМ; исчезнут после reboot.
