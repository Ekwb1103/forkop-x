# Профиль ручного перезапуска 192.168.90.1 — 8 октября 2026

Установленная сборка: локальная Forkop 2.0.0 с первыми безопасными оптимизациями, sing-box X 1.0.1-r1 (1.14.2-x-1.0.1). GL-MT6000, OpenWrt 25.12.5.

Проверен полный путь manual_restart, который использует кнопка LuCI. Выполнен один успешный контрольный перезапуск на реальном роутере. До него сохранены пакеты, службы, конфигурации и исходный модуль. Во временную диагностическую копию lifecycle.uc добавлены только отметки времени вызовов, без изменения ветвлений/таймаутов/порогов. После замера оригинальный модуль восстановлен и сравнен побайтно. Первый запуск диагностической обёртки завершился ошибкой порядка определения функции до выполнения операции; порядок исправлен, исходный runtime при этой ошибке не затрагивался.

## Дополнительные накладные расходы проверок процессов

service/state.uc определяет executable каждого PID через отдельный внешний readlink. sing_box_process_count сканирует /proc, вызывая этот helper для каждого PID. Проверки конфликтов, принадлежности procd и стабильности повторяют сканирования.

Во время диагностики около 141 процессов. Проверка sing-box-process-conflict занимала 0,69–0,72 с; финальная forkop-stably-running 0,70 с. Нельзя целиком приписать эти вызовы одному сканированию: они включают другие проверки и иногда повторное сканирование.

Без изменения установленного state.uc проведено три сравнения его read-only команды sing-box-process-count и временной копии, в которой три вызова внешнего readlink заменены на fs.readlink. Для всех вызовов найден один sing-box:

| Вариант | Три измерения |
|---|---|
| Исходный | 0,38 / 0,35 / 0,36 с |
| Временный native-readlink кандидат | 0,08 / 0,08 / 0,08 с |

Это доказанный локальный источник накладных расходов. Ускорение всего restart этой заменой пока не измерено. Перед внедрением нужны проверки обычного и удалённого executable, пропавшего PID, второго/чужого процесса и повторного использования PID; существующие проверки принадлежности процесса следует сохранить.

## UPX и ресурсы

Пять вызовов установленного sing-box version суммарно заняли 2,23 с, около 0,45 с за вызов на ARM64 роутере. Это время всего запуска/вывода версии, а не изолированная стоимость UPX: сравнение с распакованным бинарником в этой диагностике не выполнялось. Оно не объясняет десятки секунд полного restart. В validator такой вызов дополнительно обёрнут циклом sleep 1, что видно в 1,10 с check-requirements.

В начале диагностики MemAvailable около 701904 КиБ, load average 0,20 / 0,43 / 0,31. Эти наблюдения не указывают на дефицит RAM или высокую общую нагрузку как основную причину этого запуска; подробный CPU/IO профиль не выполнялся.

## Результат и следующие кандидаты

Причина длительности — последовательный полный цикл обновления данных, остановки/запуска, обработки кэшей и правил, двух DNS-переходов и проверки стабильности. Никакой один подтверждённый зависший шаг на 30–40 секунд не найден.

Приоритет следующего безопасного этапа: встроенный fs.readlink с сохранением проверок владения; затем устранение секундного ожидания успешного вывода версии с сохранением deadline. После этого повторить полный manual_restart с реальной конфигурацией. Подготовку свежих данных и восьмисекундную проверку стабильности нельзя просто убрать без изменения поведения. Оптимизацию двух DNS-переходов следует исследовать отдельно с проверкой восстановления DNS при сбое запуска.

После контрольного перезапуска Forkop/sing-box работают. SHA-256 конфигураций Forkop и sing-box и бинарника sing-box совпадают с исходными. Отдельные nfqws Zapret сохранили PID. Действующий backend восстановлен; кандидат state.native.uc не устанавливался. Raw timings сохранены локально: tmp/optimization-review-20261008/router90-profile/timings.log.
