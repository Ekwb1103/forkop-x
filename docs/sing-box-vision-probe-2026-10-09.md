# Быстрая проверка оптимизации Vision, 2026-10-09

Проверяется только патч FiyeroT/sing-vmess
`8bce78ee76de68dee2d879d990c3fbbda3b777f9`: после завершения буферизованной
части directRead цикл копирования получает underlying reader. Write остаётся
через Vision. Полная замена библиотеки не выполнялась.

Патч применён к sagernet/sing-vmess v0.2.8 в отдельной копии исходников X 1.0.2.
Go 1.26.8, upstream 1.14.2, штатные build tags, QUIC не включён.
Два теста патча (выдача buffered bytes перед direct bytes и отсутствие замены
до direct mode) прошли обычным запуском и с race detector.

## Методика и границы

Существующая OpenWrt 25 VMware VM, x86_64, Linux 6.12.94, около 986 МиБ RAM.
Штатный Forkop и sing-box продолжали работать. Пакеты, службы, UCI и firewall
не менялись. Дополнительные бинарники запускались из /tmp, loopback-порты
48101–48104; исходящий тестовый трафик использовал существующую bypass mark.
Базовый бинарник побайтово совпадает с установленным /usr/bin/sing-box.

В текущей конфигурации не нашлось пригодного TCP REALITY + Vision узла.
Вместо него использован локальный VLESS + TLS + xtls-rprx-vision сервер
с временным сертификатом; клиент использует Firefox uTLS. Через него
32/64 соединения выполняли HTTPS к www.gstatic.com/generate_204 с проверкой
сертификата внутреннего HTTPS. Это проверяет Vision с внутренним TLS 1.3,
но не внешнее REALITY рукопожатие, TUN/TPROXY ingress, ARM64 или большие передачи.
Никакие реальные учётные данные не копировались в артефакты.

RSS и Go memory относятся только к клиентскому процессу. Клиент, сервер,
генератор нагрузки и работающий Forkop — разные процессы. Метрика Go:
StackInuse + HeapInuse + HeapIdle - HeapReleased. Kernel pipe memory в этих
метриках не учитывается. CPU и пропускная способность не измерялись.

Два запуска каждого UPX-бинарника, порядок old1, new2, old2, new3.
По 10 замеров с интервалом 1 с после 5 с стабилизации; после закрытия
соединений ожидание 20 с плюс стабилизация. Без принудительного GC.
Дополнительный успешный запуск unpacked-кандидата исключён из сравнения RSS.
Один ошибочно пересекающийся запуск исключён полностью.

При 32 соединениях существенный выигрыш не обнаружен. При 64 соединениях
медианная экономия RSS клиентского процесса около 1,27 МиБ, удерживаемой

HTTPS-запросами; доверительные интервалы не вычислялись. Нельзя утверждать
такой же выигрыш в общей памяти роутера: дополнительная память pipe относится
к ядру Linux. Рост FD примерно на два на соединение согласуется с pipe для
splice. После закрытия корректных прогонов FD вернулись к 10.

Дополнительный сервер остановлен; штатные Forkop и sing-box работают, SHA-256
/usr/bin/sing-box сохранился. Установка, публикация и интеграция патча в X
не выполнялись.

Вывод: узкий патч применим и прошёл базовую проверку корректности, race и
короткую нагрузку; размер практически не изменился. Умеренный выигрыш памяти
процесса обнаружен при 64 соединениях. Скорость/CPU, суммарная память системы,
реальный REALITY, ARM64 и длительная стабильность ещё требуют отдельных тестов.

## Дополнительная проверка настоящего REALITY + Vision

После первоначальной проверки пользователь предоставил подписку. Запрос со
штатными заголовками INCY и HWID существующей VM вернул 58 TCP REALITY + Vision
узлов. Без полного профиля сервер отдавал сообщение «Приложение не поддерживается».
Ссылка, HWID, адреса узлов и credentials в отчёт и локальные артефакты не включены.

Выбран один TCP VLESS REALITY + xtls-rprx-vision узел с Firefox uTLS.
На одинаковой конфигурации выполнены четыре последовательных запуска:
baseline old1, candidate new1, candidate new2, baseline old2. Оба бинарника
UPX; принудительный GC не использовался. Методика и 32/64 HTTPS-соединения
такие же, как выше; теперь внешнее соединение действительно использует REALITY.

Все 160 замеров четырёх прогонов прошли строгую проверку:
active = API connections = target, errors = 0. Пропущенных фаз нет.
Числа ниже — медиана средних двух запусков каждого варианта.

| Состояние | RSS X, МиБ | RSS Vision, МиБ | Go X, МиБ | Go Vision, МиБ | FD X / Vision |
| --- | ---: | ---: | ---: | ---: | ---: |
| Простой | 30,81 | 30,81 | 2,39 | 2,40 | 10 / 10 |
| 32 соединения | 36,08 | 36,02 | 6,40 | 6,20 | 75 / 139 |
| 64 соединения | 39,49 | 37,74 | 9,50 | 7,59 | 139 / 267 |
| После закрытия | 40,69 | 38,66 | 10,74 | 8,54 | 11 / 11 |

На настоящем REALITY + Vision при 64 соединениях подтверждён умеренный выигрыш:
около 1,75 МиБ RSS процесса и 1,90 МиБ удерживаемой памяти Go. При 32 соединениях
разница RSS около 0,06 МиБ — практически несущественная. Это не обещание линейной
экономии при увеличении числа соединений. FD увеличиваются примерно на два
на соединение и освобождаются после закрытия.

Ограничения сохраняются: один узел, x86_64, mixed ingress, редкие HTTPS-запросы,
два запуска; не проверены CPU, throughput, ARM64, TUN/TPROXY ingress, общая RAM
с учётом kernel pipe и длительная стабильность. Это проверка совместимости
с данным REALITY узлом, не со всеми серверными версиями и fingerprints.

Анонимные данные: work/vision-probe/evidence/remote-*.tsv, итоговая строгая
сводка work/vision-probe/remote-summary.json. Временная подписка, конфигурация
с credentials и приватные логи на VM удалены. Штатные службы работают,
SHA-256 установленного бинарника не изменился. Патч не интегрирован и не опубликован.
