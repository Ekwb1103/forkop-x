## Общая оценка

Полезный инженерный набор исправлений sing-box для OpenWrt: есть объяснения конкретных отказов, лабораторные сценарии, регрессионные тесты, пакетные проверки и матрица REALITY. Положительные признаки сильнее простого перечня новых функций. Однако 88 патчей за короткий период, особенно большой новый XHTTP, увеличивают объём собственного сопровождения. Результаты производительности автора не являются измерениями нашего X.

Проверенный workflow содержит сборку, установки в OpenWrt rootfs, конфигурационные проверки и REALITY gate; явного запуска всего добавленного набора Go unit/race tests в workflow и sdk-build.sh не обнаружено. Наличие тестов не подтверждает их запуск на каждом выпуске. Наш перенос должен сделать их обязательными для затронутых пакетов и включить race tests.

Уже испытанный Full запускает Forkop, но наши тесты не включали реальные прокси-серверы. Его пакетная автоматика меняла UCI и запускала собственную службу. Переносить нужно изменения ядра, сохраняя нашу упаковку, зеркало, подписи, откат и управление службами.

## Этап 1: устойчивость и совместимость

1. Проверка входных данных и защита сниффера: 0015, 0038, 0041, 0084; 0039 для закрытия соединений вне group lock. В исходной базе X присутствуют соответствующие старые конструкции: неограниченная сборка CRYPTO, закрытие под lock и старый sing-vmess v0.2.8. Защита QUIC актуальна даже без QUIC transports: sniffing остаётся. Проверить upstream commits 07512b109, d2cf9747d и sing-vmess 9b95ab8, предпочитая минимальный upstream backport. 0038 из podkop намеренно не включает QUIC-sniffer часть, поэтому отдельно взять 0015. Не считать одно лишь recover полноценным исправлением границ.
2. REALITY/uTLS: 0001, 0002, 0010, 0085 как согласованный набор. Текущая база X удаляет X25519MLKEM768 из Hello и сообщает REALITY client version 1.8.1. Изменение Hello и версии клиента требует собственной матрицы старых/новых Xray, fingerprint, ALPN, TCP/gRPC, Vision и обычного TLS. Это совместимость с требованиями сервера; не обещать полную поддержку всех постквантовых расширений Xray.
3. gRPC-lite/HTTP2: 0017, 0070; readwait 0029–0031 отдельно после проверки. Не переносить QUIC части 0031 в используемый X без необходимости. Протестировать недоступный сервер, обрыв handshake, Close, повторные соединения, отсутствие goroutine/socket leaks и race.
4. DoH: 0025, с проверкой конкурентных запросов и полного зависания соединения. Один timeout не должен сбивать успешные параллельные ответы, но мёртвый transport обязан восстанавливаться.

## Этап 2: память и накладные расходы

- 0026 обязательно вместе с 0086: освобождение состояния uTLS handshake, повторный HandshakeContext после освобождения. Проверить tls wrappers и REALITY.
- 0043: не форматировать Clash API logs без подписчиков; сохранить обычный журнал и проверить subscribe/unsubscribe.
- 0027, 0075, 0082–0084: ограничение повторных сообщений, сохраняя первый сбой, причину и сводный счётчик. 0075 связан с provider fallback и отдельно без него не нужен.
- 0032: динамический Go memory limit перспективен, но отдельный эксперимент. Проверить OpenWrt 24/25, ARM64 и x86_64, UPX, cgroup без/с лимитами, GOMEMLIMIT/debug override, нехватку RAM, GC CPU и throughput. Soft limit не гарантирует отсутствие OOM и не должен считаться экономией flash.
- Vision/readwait изменения sing-vmess: upstream input-validation fixes отделить от собственного splice/память-fork. Не переключать всю зависимость на pdk только ради backport. Если нужен fork — зафиксировать точную ревизию, исходники и весь набор регрессий.

## Этап 3: новые возможности

- XHTTP: цель полезна, но переносить полный согласованный набор 0046–0054, 0057–0064, 0069, 0071–0073 с зависимостями TLS/options, а не только первый патч. Первый патч явно назывался work in progress; последующие меняют отмену, upload, Close, pooling и HTTP/3. Сначала вариант HTTP/1.1+HTTP/2 с явным отказом HTTP/3 при отсутствии with_quic. Код содержит http3_stub, но сборку без QUIC и все режимы нужно проверить. Не включать with_quic автоматически: измерить plain/UPX payload и dependency graph.
- 0068 Features: перенести идею, публикуя только действительно собранные возможности. Текущий Forkop передаёт supports_xhttp через sing_box_is_extended, поэтому наличие XHTTP в X потребует изменения определения возможностей backend и frontend.
- decode-link: 0055–0056, 0065–0067 — факультативно. Forkop уже имеет собственный parser; решать после сравнения форматов ссылок, схемы extra, ошибок и стратегий fallback. Секреты ссылок не должны попадать в журналы.
- urltest: 0021–0023, 0028, 0033, 0036–0037, 0042, 0087 — отдельный feature project. 64 KiB тест и внеочередные проверки меняют трафик и выбор узлов; сделать управляемыми и ограниченными. Проверить взаимодействие с priority groups/selector и сохранением выбора Forkop, без дублирующих probes.

## Не переносить автоматически

- Provider DNS fallback 0007/0009/0074–0079: включать только явной политикой. Подмена DoH/DoT ответов DNS провайдера может вернуть блокировки и изменить приватность. Автор ограничивает eligible servers и исключает proxied/VPN/private; эти ограничения всё равно нужно проверить с нашими routing_mark/bind_interface и dns routing.
- FakeIP memory store 0011/0080/0081: большой выигрыш возможен, но около 170 байт heap на имя по оценке автора, миграция bbolt, eviction и гарантии crash/rollback требуют отдельного проекта. 0080 сознательно допускает повторное назначение адреса другому домену после crash при отказе записи — это меняет корректность маршрутизации.
- FakeIP sniff fallback 0013/0082: после потери записи destination берётся из SNI/Host; проверить приоритеты domain/IP routing и поведение без имени/ECH. Это изменение семантики, а не просто ускорение.
- Start-empty rule sets 0004/0020/0045/0088: у Forkop уже есть проверенный persistent SRS cache и fallback. Пустой список может направить трафик по default route. Не вводить второе управление кэшем и podkop hooks; сначала определить fail-open/fail-closed для каждого правила.
- UDP queue 0014: увеличение 64 → 1024 требует нагрузочного сравнения RAM/latency/drops; больше очередь не всегда лучше на малой RAM.
- Slim/full protocol registry, удаление TUN, NaiveProxy/QUIC transports, podkop init/failsafe/hooks: не соответствуют текущим границам X. Native API уже исключён нашей схемой, а system TUN/Clash API/gRPC-lite необходимо сохранить.
- 0044 background Clash listen retry: полезная идея, но Forkop readiness требует Clash API; согласовать degraded state и UI/watchdog, иначе ядро работает, а Forkop запускает recovery.

## Условия выпуска

Составить manifest патчей с авторством/лицензией и зависимостями; сохранить GPL notices и полный соответствующий исходный архив. Начать с отдельного bugfix-кандидата, затем memory-кандидат, затем XHTTP. Никакой смены upstream version в строке X для собственной версии сборки: сохранить три отдельные версии.

Для каждого этапа: unit tests и race для изменённых пакетов, CGO_DISABLED production build на ARM64/x86_64, dependency exclusions native API/gVisor/QUIC transports, UPX integrity, extracted payload/flash план, подписанные mirror APK/IPK, точный rollback. На существующих OpenWrt 24/25 — конфигурация, start/restart, DNS/API, реальные протоколы на контролируемом сервере, WAN failure/restore, память/нагрузка и восстановление после неуспешного обновления. Проверить сохранение наших Clash match evidence при правках route/rule и clashapi.

Изменения в ядро/VM в этой оценке не внесены. Скачаны исходники для статического сопоставления.
